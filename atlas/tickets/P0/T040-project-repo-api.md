# T040 — Project repo + read API

**Goal:** `lib/repos/project.ts` is the ONLY place that reads `atlas.projects`. Returns `ProjectInput` shape — calc-engine-ready out of the box. `/api/projects` + `/api/projects/[id]` wire the repo behind the standard envelope + auth.

## What changed

### New files

- `atlas/lib/repos/project-row-to-input.ts` — converter: maps a `ProjectRow` (DB shape: cents, basis points, snake_case) → `ProjectInput` (calc-engine shape: dollars, decimals, vanilla field names). Handles cents↔dollars, bps↔decimal, JSONB breakdown, and derives the legacy mirror fields (`villa_sqft = ag + bg`, `start_date = purchase_date`, `program_months = sum of 4 buckets`).
- `atlas/lib/repos/project.ts` — `findManyProjects(opts)` + `findCurrentProjectByKey(key)` + `findProjectRowById(uuid)`. Uses `createSupabaseServerClient()` from T009; service-role bypass not needed because SELECT-only and we leverage the authenticated-read RLS policy from T020.
- `atlas/app/api/projects/route.ts` — `GET /api/projects` with `stage`, `status`, `q`, `limit`, `cursorKey`+`cursorCreatedAt` query params. Returns `{ data: { projects, nextCursor } }`.
- `atlas/app/api/projects/[id]/route.ts` — `GET /api/projects/[id]`. Resolves by stable `project_key`. 404 with `PROJECT_NOT_FOUND` when missing.
- `atlas/lib/repos/__tests__/project-row-to-input.test.ts` — 7 invariants covering cents/bps conversion, null pass-through, soft-cost breakdown, legacy mirror derivation.
- `atlas/scripts/generate-seed-sql.mjs` — Node script that imports `public/data.js::BASELINE_PROJECTS`, converts each to DB column shape (dollars→cents, decimals→bps), and writes `seed-baseline-projects.sql`. Idempotent + commitable.
- `atlas/migrations/0005_seed_baseline_projects.sql` — applied-migration marker (full SQL is regenerated by the script; not duplicated in the repo).

### Live Supabase

Applied `atlas_seed_baseline_projects` migration: **10 rows in `atlas.projects`** (p2 through p11), all `is_current=true`, `is_archived=false`, version 1. Verified via `list_tables`.

## Conventions enforced

- Repos are SELECT-only; mutations live in `lib/services/project.ts` (T044+)
- Conversion happens at the boundary (DB row → ProjectInput); calc engine + surfaces never see cents/bps directly
- Cursor pagination uses `(created_at, project_key)` pair for stable ordering — opaque to consumers, just pass back what the response gave you in `nextCursor`
- All filters compose; the `q` substring search runs ILIKE against `name` and `address`
