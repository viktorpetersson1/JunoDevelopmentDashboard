# PHASE 4 — Validation against the Excel model

## v3 reconciliation workflow (recommended for management use)

To match Excel as closely as possible, in **Settings**:
1. **Fiscal year mode** → "Juno 13-month (Jan 2030 rolls into FY29)"

Then per project (Project detail → "Use Excel sale price" button):
2. Click **Use Excel sale price** on each project to set `sale_price_override_usd`. Or run the bulk apply via the JS console: `state.projects.forEach(p => updateProject(p.id, { sale_price_override_usd: p._excel_sale_price }))`.

Result: **Total sales match Excel within $1,594** (0.002%). Profit gap shrinks to $5.6M (45%), entirely attributable to the dashboard reporting the *full* build cost while Excel's monthly grid under-allocates by $5.4M.

For day-to-day scenario work without exact-match: leave defaults (calendar FY, cost-plus-margin pricing) — the dashboard is more conservative and directionally reliable.

## 4. Why outputs still differ in v2

| # | Variance source | v2 status |
|---|---|---|
| V1 | **Fiscal year bucketing** | **Fixed**. Toggle `fiscal_year_mode = "juno13"` in Settings to match Excel. Default is `calendar` (more conventional). |
| V2 | **Cost spreading shape.** Excel spreads each build sub-line over hand-crafted month windows on the Project 2 tab. Other projects copy that shape. Excel's monthly sum of build costs ($23.6M) is materially **less than the project totals on `M14`** ($29.0M). | **Known Excel under-allocation**. Dashboard spreads the full `M14` evenly over 13 months. Result: dashboard reports the true total build cost, which is $5.4M higher than Excel's apparent monthly sum. Documented; no engine change. |
| V3 | **Financing.** | **Fixed**. Added `financing_fees_per_project_usd: $350k` (covers Excel rows 65–70). Dashboard now reports $6.63M total financing vs Excel's $6.48M (within 2.4%). |
| V4 | **Soft costs.** Per-project `soft_costs_lump_sum` field — zero by default. | Available; users can populate from contract data. |
| V5 | **Opex** flat $475k/yr; Excel has slight FY26 (ramp) and FY29 (escalation). | Close enough (within $80k/yr); v2.x could add an opex growth rate. |
| V6 | **Project 2 build override** at $437/sqft, captured in `data.js`. | Match. |
| V7 | **Sale price methodology** — Excel grosses up sale price using cost+financing as basis; dashboard uses cost-only. | $1.35M total under-statement in dashboard. Document; users can override per-project sale price if needed. |

**Both differences (V2 build under-allocation, V7 sale price gross-up) are conservatively biased in the dashboard.** A user wanting to match Excel exactly would:
1. Enable "Juno 13-month FY mode" in Settings (already toggle-able)
2. Manually set sale price per project to match Excel's M27 values (per-project override field exists)
3. Accept the higher build cost as the truthful figure

## 6. v2 features summary

### New in v2

- **IRR per project + portfolio.** Bisection-based monthly IRR, annualized to (1+r)^12 − 1.
- **MOIC per project.** Sum of equity returned ÷ sum of equity drawn.
- **Investor waterfall view.** Replicates Excel's KPC Equity Flow tab structure: per-project equity-in/equity-out/MOIC/IRR/hold, by-FY annual table, cumulative line chart, monthly drawn/returned bar chart.
- **Tornado chart on Sensitivity.** Horizontal bar chart ranked by absolute profit impact across five drivers (sale price, build cost, margin, interest rate, timing).
- **Financing fees driver.** $350k per project default, matches Excel rows 65–70 line items.
- **Fiscal year toggle.** Calendar (Jan–Dec) or Juno 13-month (Jan 2030 rolls into FY29).
- **Capitalize interest toggle.** Simple (Excel default) or compound.
- **CSV exports** for cash flow grid, projects list, annual P&L.

### Shipped in v3

1. **Per-project sale price override** — `sale_price_override_usd` and `sale_price_per_sqft_override` fields. "Use Excel sale price" button on each project's detail page pre-fills the override with the Excel benchmark value.
2. **Opex growth rate** — new `opex_growth_rate` global driver, applied per fiscal year.
3. **Soft cost subcategories** — `soft_costs` object with 7 named line items (build_tools, sabbeth, craft, zero_design, klas_bsv, permits, other). Falls back to the legacy lump sum if all subcategories are zero.
4. **Build cost spreading curves** — global `build_cost_curve` selector: linear (default), front-loaded, or s-curve. Kingshaus always uses s-curve (matches reality of mid-build panel delivery).

### Still pending for v4

1. **84 SBR detailed takeoff integration** — wire `Construction costs 84SB` line items directly into Project 2's monthly schedule.
2. **External Kingshaus unit costs** — read `6 GC - SE Costs.xlsx` actual unit prices for panels / windows / façade / structural design / production / assembly / logistics.
3. **Investor-level breakdown on Waterfall view** — split equity by investor (KPC vs co-investors) with different equity shares.
4. **Per-project build cost curve override** — let individual projects pick their own curve (currently global only).
5. **Two-way sensitivity analysis** — heatmap of two drivers (e.g. interest × build cost).
